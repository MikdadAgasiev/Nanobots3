Version: 5.8.7
Date: 2026-06-16
  Bugfixes:
    - Actually fixed the "Cannot serialise ttype=function" crash on load with Pyanodons Post Processing (pypostprocessing). The real cause is stdlib2's Data/Recipe wrappers attaching function-carrying metatables to prototypes during the data stage; pypostprocessing serialises data.raw and chokes on them. Removed stdlib2 from the entire data stage and rebuilt those prototypes with native data:extend: sounds, all five equipment-bot-chip files, make_shortcut, roboport-interface (vanilla combinator/radar now copied via util.table.deepcopy, empty graphics via util.empty_sprite/empty_animation, recipe unlock via a direct technology effect), and the bob-mods recipe edits in data-updates.lua (native in-place ingredient editing). Runtime scripts still use stdlib2, which is fine because the control stage is not serialised.
    - The v5.8.6 data-final-fixes approach (stripping metatables after the fact) did not work because the crash happens earlier, during the data stage; it has been removed in favour of this proper fix.
